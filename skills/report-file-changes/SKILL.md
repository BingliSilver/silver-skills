# 报告会话文件变更

跟踪当前用户任务实际造成的文件变化，并在任务完成时提供准确、可核对的文件清单。

## 确定基线

- 在第一次写入前，记录足以区分“本次任务变更”和“用户已有变更”的基线信息。
- Git 仓库中可以参考工作区状态，但必须结合本次实际编辑和命令执行记录进行判断，不能仅依赖仓库整体的脏文件状态。
- 非 Git 目录中，根据任务范围记录目标文件是否存在；必要时补充文件哈希、时间戳或内容快照，确保完成时能够判断净变化。
- 不修改、覆盖或回退与当前任务无关的用户变更。

## 跟踪范围

- 记录 Codex 直接修改的文件，以及 Codex 执行的命令所创建、编辑、重命名、移动、格式化或生成的文件。
- 每个最终绝对路径只统计一次。路径必须包含文件名，不能只报告目录或相对路径。
- 文件在基线时不存在、完成时存在，分类为 `新增`；其他存在净变化的文件分类为 `变更`。
- 重命名或移动只报告最终目标路径。
- 排除只被读取的文件、任务开始前已经存在且与本次任务无关的变更，以及最终内容已完全恢复到基线状态的文件。
- 仅代表删除结果的路径默认不报告；只有用户要求报告删除文件时才纳入。

## 完成前核对

- 完成全部编辑、格式化、生成和验证命令后，再核对最终文件清单。
- 确认没有漏记命令生成的文件，也没有误收只读文件或用户原有变更。
- 按最终绝对路径去重，然后依据文件数量选择报告方式。

## 不超过 30 个文件

当最终清单包含 30 个或更少文件时，在最终回复中直接加入：

```markdown
本次会话新增或变更的文件（N 个）：

- 新增：`C:\absolute\path\file.ext`
- 变更：`C:\absolute\path\another.ext`
```

仅保留实际存在的分类和条目，并确保 `N` 与去重后的条目数一致。

## 超过 30 个文件

当最终清单超过 30 个文件时：

1. 在当前任务的工作目录创建 UTF-8 编码的 Markdown 文件，名称使用 `codex-session-file-changes-YYYYMMDD-HHmmss.md`。
2. 如果该文件名已经存在，在扩展名前依次追加递增数字后缀，禁止覆盖已有报告。
3. 将报告文件自身作为 `新增` 文件计入总数，并在报告中包含它的绝对路径。
4. 在报告开头写明总数，然后将所有唯一绝对路径分别归入 `新增文件` 和 `变更文件`；每个列表项都必须包含文件名。
5. 最终回复只说明文件总数并提供报告的绝对路径或可点击的本地文件链接，不要再次粘贴完整清单。

## 没有净变化

如果当前任务最终没有新增或变更任何文件，不创建空清单；只需明确说明本次任务没有新增或变更文件。
