# 归并零散知识文档

将同一知识目录中的零散 Markdown 从“多篇局部笔记”整理为“一篇结构清晰、信息完整的知识文档”。以源文档为事实边界，进行语义归类和去重，不凭空补充未经来源支持的知识。

## 工作流程

### 1. 确定来源目录和文件范围

- 用户已经提供知识文档文件夹时，优先使用该路径。
- 用户未提供路径但当前会话明确关联项目或工作区时，优先检查 `<项目根目录>/learning/`。
- 不存在项目或无法确定知识目录时，先要求用户提供源文件夹绝对路径，不要擅自使用用户主目录、桌面、临时目录或技能目录。
- 确认目录存在且可读，列出其中的 Markdown 文件。默认只扫描该目录本层；只有用户明确要求时才递归扫描子目录。
- 排除明显不属于知识笔记的 README、变更记录、需求文档和项目说明。无法判断文件是否应纳入时，列出候选并向用户确认范围。
- 如果没有可归并的 Markdown，直接说明，不创建空文档。

### 2. 建立知识清单

- 完整读取所有纳入范围的源文档，不要只根据文件名、标题或摘要进行归并。
- 为每篇文档识别核心主题、子主题、关键结论、成立条件、版本差异、机制推导、代码示例、反例、易错点和排查步骤。
- 建立由基础概念到具体机制、适用边界和实践方法的知识层级，识别各文档之间的前置、补充、重复、包含和冲突关系。
- 区分文字相似与语义重复。表达角度不同但能补充原因、边界、反例或使用条件的内容不属于无效重复。
- 对来源中缺少依据、互相矛盾或标记为待验证的结论保留不确定性，不自行当作已确认事实。

### 3. 强制确认写入方式

在修改任何文件前，必须让用户明确选择以下一种方式：

1. **追加到已有 Markdown**：列出目录中适合作为归并目标的候选文档，并要求用户指定确切文件；用户已经指定文件时不重复询问。
2. **生成新的 Markdown**：允许用户指定文件名或标题；用户未指定时，根据主要知识范围生成能够概括归并主题的中文名称。

不要根据文件数量、名称或内容擅自替用户选择。若用户已在调用请求中明确给出“追加”或“新建”及必要路径，则视为已经完成确认。

选定目标文件后，将它从普通源文件列表中单独标记，避免把目标文档重复合并进自身。

### 4. 执行知识归并

- 按概念关系重新组织知识，而不是按源文件顺序机械拼接全文。
- 保留每篇源文档中正确、独有且有学习价值的内容，包括具体机制、成立条件、推导过程、代码示例、失败场景、反例和排查步骤。
- 将语义等价且没有新增信息的表述合并为一次完整说明，删除明显重复内容，但不要为了缩短篇幅牺牲有效细节。
- 将分散在不同文档中的互补知识放入同一主题下，使结论、原因、边界和示例彼此邻近。
- 来源结论冲突时，优先判断是否由版本、实现、配置、运行环境或适用条件不同造成，并在归并文档中明确区分。无法消解时并列保留观点及其来源前提，标记为待验证，不静默选择其中一个。
- 保持术语一致；第一次出现时说明容易混淆的概念，后续使用统一名称。
- 保留代码块的语言标记和关键解释。只有能保证语义不变时才合并重复代码，不编造运行结果或测试结论。
- 不把项目特定实现描述为语言、框架或中间件的普遍保证。

### 5. 追加到已有文档

- 在修改前完整读取目标文档，识别其 frontmatter、标题层级、目录、段落长度、列表方式、表格形式、术语、代码块、链接、提示块和整体语气。
- 遵循目标文档已有格式和主导写作风格，将新知识放入语义最合适的现有章节；确有必要时再按原有层级新增章节。
- 采用范围尽可能小的局部编辑。保留原文中仍然正确的知识、有效示例、必要前提和有价值的细节。
- 删除合并后明显重复、语义等价且没有新增信息的内容，但保留能解释不同角度、边界或反例的段落。
- 不要仅为统一措辞、调整文风、重排版式或展示归并效果而重写整篇文档。
- 不要降低原文的信息密度，不得用宽泛摘要替换具体机制、成立条件、推导过程、代码示例、失败场景或排查步骤。
- 不修复与本次归并无关的格式或内容问题。若原有结构确实阻碍知识合并，只进行容纳新知识所必需的结构调整。

### 6. 生成新文档

- 将所有纳入范围的知识组织成一篇能够脱离源文档独立阅读的文档。
- 根据内容建立清晰的主题层级。通常按照“范围与边界、核心概念、工作机制、关键结论、示例、常见误区、实践建议”的逻辑组织，但不要机械填充空章节。
- 文档较长时增加简洁目录或知识导航；保持章节粒度均衡，避免单个巨大章节或过度碎片化的小标题。
- 用户未指定文件名时，使用能够直接概括归并后知识范围的简洁中文文件名，不添加日期前缀。例如使用 `Java并发锁机制与实践.md`，不要使用含义宽泛的 `知识归纳.md`、`合并文档.md` 或无语义的编号名称。
- 生成文件名时移除 `\\ / : * ? " < > |` 等文件系统不允许的字符，并去除末尾的空格或句点；正文一级标题可以保留完整、自然的中文标题。
- 新文件与已有文件同名时不覆盖原文件，依次尝试在扩展名前追加 `-2`、`-3` 等序号，直到得到目录中不存在的文件名。

### 7. 写入与保护

- 无论追加还是新建，都严格使用 UTF-8 编码，保留中文、代码和标点的正确字符。
- 不删除、移动、清空或覆盖源文档。归并完成后默认保留全部原始零散文档，只有用户另外明确要求时才处理它们。
- 不修改未纳入归并范围的文件。
- 写入失败或目标无权限时，说明具体原因并要求用户提供可写路径或完成必要授权。

### 8. 质量检查

写入后重新读取目标文档并确认：

- 每篇纳入范围的源文档中有价值且不重复的知识都已被保留，没有因压缩而降低信息密度。
- 重复内容已经合并，互补内容已经归类，冲突内容已经按条件区分或明确标记待验证。
- 追加模式下，目标文档原有的正确内容、结构层级和主导风格仍然保留，不存在无理由的整篇重写。
- 新建模式下，文档能够独立阅读，章节顺序符合知识依赖关系，不是源文档的简单串联。
- 文件可按 UTF-8 正常读取，不含乱码，代码围栏、标题层级、表格和链接结构完整。
- 所有源文档仍然存在且内容未被修改。
- 最终向用户说明本次采用追加还是新建模式、目标文件路径、纳入和排除的文件数量，以及归并后的主要知识结构。
